# Hermetic suites that are NOT safe to run concurrently with their siblings.
# Format: scripts/tests/<filename> # <reason>
#
# The reachability gate runs the hermetic manifest concurrently, because running
# all 130 suites serially cost 1260s and made `local-ci --fast` slower than the
# entire pre-jul27_pm_4 gate set. Concurrency was validated against a serial
# oracle: the serial run passes all 130, so any suite failing only in the
# concurrent run is contending on shared state, not genuinely broken.
#
# Suites listed here either failed empirically under concurrency 8 or share the
# same checkout-root state mutation pattern that caused the observed failures.
# Each suite remains in the serial tail only until it has per-suite isolation.
#
# They are "hermetic" in the reachability audit's sense (no deployed
# environment, no live credentials) but not isolated from each other: they drive
# the local dev stack, shared fixture state, or timing-sensitive subprocess
# contracts, so concurrent suite load can change their verdict.
#
# This registry is a scheduling fact, NOT a skip list. Every suite here still
# runs on every gate invocation — just sequentially, after the concurrent batch
# drains. Removing a line makes its suite run concurrently again; it never makes
# it stop running.
#
# The right long-term fix is per-suite isolation (unique compose project names,
# unique temp roots) so these can rejoin the concurrent batch. Until then, this
# file records the measured truth rather than hiding it behind a slow serial
# gate or, worse, a quarantine that stops running them.
#
